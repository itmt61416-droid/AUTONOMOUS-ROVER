# Rover API and telemetry contract

Base URL: `http://localhost:5000`. JSON uses UTF-8. Contract version is `schema_version: "1.0"`. The browser and laptop integration should use these endpoints; update this document in the same change as any breaking API edit.

## Telemetry object

`GET /api/v1/telemetry` returns one current snapshot:

```json
{
  "schema_version": "1.0",
  "timestamp": "2026-10-08T10:30:00+00:00",
  "source": "simulator",
  "connection": "connected",
  "mode": "AUTO",
  "mission_state": "RUNNING",
  "command": {"code": "F", "label": "FORWARD"},
  "distance_m": 1.24,
  "speed_percent": 42,
  "sensors": {"front_cm": 78.2, "left_cm": 65.0, "right_cm": 83.1, "rear_cm": 110.0, "obstacle_detected": false},
  "encoders": {"left_ticks": 552, "right_ticks": 558, "left_m": 0.62, "right_m": 0.62},
  "vision": {"line_detected": true, "line_offset_px": -3, "apriltag": {"detected": false, "id": null}},
  "safety": {"estop": false, "reason": null}
}
```

### Field meaning

- `timestamp`: ISO 8601 timestamp with timezone; generated by the data source.
- `source`: `simulator`, `esp32`, or `vision-bridge` (agree on the real producer before integration).
- `connection`: producer link state such as `connected` or `disconnected`.
- `mode`: `AUTO` or `MANUAL`; this describes mission mode and does not grant direct motor control to the web page.
- `mission_state`: `RUNNING`, `PAUSED`, or `STOPPED`.
- `command.code`: `F`, `L`, `R`, or `S`; decision made by the vision/laptop layer. `S` is stop.
- `distance_m`: overall distance estimate in metres. `speed_percent`: display-only 0–100 estimate.
- `sensors`: four ultrasonic distances in centimetres and an obstacle flag. The ESP32 must enforce its own safety threshold.
- `encoders`: raw tick counts and per-side distance in metres; optional on ingest.
- `vision`: line state/offset and AprilTag detection. AprilTag `id` is integer or null.
- `safety`: ESP32 safety status. `estop` is authoritative; `reason` is a short code/text or null.

The ingest endpoint currently requires all top-level properties, numeric `distance_m`, four numeric distance readings, and a valid command code. Extra fields are accepted. Keep required sensor fields present even when the value is stale; report producer disconnection in `connection`.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/health` | Process, simulator, and mode status |
| `GET` | `/api/v1/telemetry` | Current shared telemetry snapshot |
| `GET` | `/api/v1/events?limit=30` | Recent in-memory events; limit 1–100 |
| `POST` | `/api/v1/telemetry` | Laptop bridge posts a telemetry snapshot |
| `POST` | `/api/v1/commands` | Mission-level action: `start`, `stop`, `pause`, `resume` |
| `POST` | `/api/v1/simulator` | Enable/disable demo telemetry with `{"enabled":true}` |

### Ingest example

```http
POST /api/v1/telemetry
Content-Type: application/json
```

Body is the telemetry object above, with `source` set to the actual producer. Response is `{"ok":true}`. Invalid requests return HTTP 400 with `{"error":"..."}`.

### Mission command example

```json
{"action":"pause"}
```

Valid actions are `start`, `stop`, `pause`, `resume`. A valid transition returns `{"ok":true,"message":"Mission paused"}`; a safety conflict returns HTTP 409. In this starter, actions change dashboard mission state only. The future adapter must preserve ESP32 authority and must not equate an HTTP success response with verified physical actuation.

## Update cadence and ownership

The demo emits at 2 Hz; the dashboard polls at 2 Hz. The live bridge may use a different rate after measuring load. Vision owns `command` and `vision`; ESP32 owns `sensors`, `encoders`, and `safety`; the bridge combines them and timestamps the resulting snapshot. Resolve conflicting ownership before introducing a real producer.
